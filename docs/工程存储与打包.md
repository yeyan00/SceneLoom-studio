# 工程存储与打包

## 打开已有 Potree

```text
数据目录/
├─ A/                         # 已有点云，原地读取
│  ├─ metadata.json
│  ├─ hierarchy.bin
│  └─ octree.bin
└─ A.sceneloom/
   ├─ project.sceneloom.json   # dataset.source 指向 ../A
   └─ project.db
```

多个 Potree 目录分别关联自己的工程，无需原始 LAS。普通保存只写工程编辑状态；手动迁移时必须保持数据及工程的相对位置，也可以直接使用打包功能。

## 打开 LAS / LAZ

```text
数据目录/
├─ A.las
└─ A.sceneloom/
   ├─ project.sceneloom.json
   ├─ project.db
   └─ pointcloud/
      ├─ metadata.json
      ├─ hierarchy.bin
      └─ octree.bin
```

转换完成后打开工程即可使用，不依赖原始 LAS。设置统一数据目录时，整个 `A.sceneloom` 放到设置的目录；已有转换关联可复用。工程记录原始文件关联，方便打包时选择附带原始文件。多份源文件产生各自工程，名称冲突按源身份区分。

## 使用打包工程

1. 点击“打包工程”。当前工程默认选中，也可以浏览并扫描目录，选择多个工程。
2. 输入或浏览目标目录。可选附带有关联的原始 LAS/LAZ；只有 Potree 的工程同样可以打包。
3. 同名工程选择自动重命名或跳过，点击开始打包。查看逐项进度及结果，可取消正在执行的任务。
4. 整体复制输出工程目录，在新位置打开其中的 `project.sceneloom.json`，也可打开整个工程目录。

每个输出工程都有自己的 `pointcloud`、`project.db`、工程入口和文件校验清单 `package-files.json`。已有本地 `attributes/` 一并复制；附带的原始文件放在 `original/`。多个工程分别输出，不合并八叉树，也不生成 ZIP。

打包前提交当前工程的最新恢复状态，后台在复制大数据前捕获数据库快照。输出将该快照作为已保存状态，保留撤销和重做历史；原工程保存点不变。复制期间继续编辑不会改变已经捕获的输出快照。

点云文件流式复制并计算 SHA-256，检查复制前后的源文件大小和时间；最后才发布工程入口。输出以相对路径关联点云，保留原数据集标识和编辑版本。移动后时间戳变化时校验内容，避免编辑记录因路径改变失效。内容校验可能需要读取完整文件。

取消或某项失败会清理该项未完成输出，已成功项目保留；单项错误不阻止其他项目。拒绝把目标放入源工程或点云内部，不覆盖已有目录。任务仅在当前后台服务运行期间管理，暂不支持重启续传；意外断电可能留下没有工程入口的未完成目录，可核实后删除。

## 保存与导出的区别

保存工程记录编辑规则、历史、类别定义和工作区；删除保持逻辑删除，分类由加载节点按历史计算。打包复制原点云并携带这些编辑状态，保持八叉树结构。物理删除、把分类写入原 bin、标准 LAS/XYZ 导出、增加逐点自定义属性及重建八叉树仍需后续独立工具实现。

数据库后缀统一为 `.db`。旧 `.sqlite` 和用户目录中的旧工程通过一致性备份迁移，保留旧文件。正在使用的工程可能存在数据库临时文件，跨设备携带请使用打包功能，不单独复制 `project.db`。

## 验证入口

`npm.cmd run test:package` 验证浏览器扫描、批量选择、目录浏览、携带原始文件、未保存编辑、进度、中英文和窄屏，以及断开源数据后重开。`npm.cmd run test:integration` 另覆盖目录迁移、时间戳变化校验、同名策略、取消清理、损坏项隔离、扩展属性复制和旧数据库迁移。真实转换布局由 `npm.cmd run test:converter` 验证。

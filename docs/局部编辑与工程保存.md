# 局部编辑与工程保存

## 使用方式

1. 打开 Potree 数据，选择“局部截取”。在主视图点击中心线起点、终点，移动鼠标调整两侧宽度，再次点击确认；Esc 取消。截取基于穿过当前观察目标的水平平面，不是表面拾取。
2. 工作区显示主视图与局部顶视、正视、侧视。子视图默认锁定方向，右键平移、滚轮缩放；可解锁旋转、恢复方向、适应或最大化。区域宽度和上下高度可输入调整，高度使用数据集坐标，单位与源数据一致。
3. 使用矩形或多边形工具，选择替换、并集、减选或交集；结果在各视图高亮。多边形双击完成，Esc/清除选区取消。切换矩形与多边形不会丢失已有组合选区。
4. 指定目标类别后点击赋类，或点击删除选区，一次确认产生一个撤销步骤。局部区域存在时所有视图的编辑均限制在该区域，反选也只在该区域求补集；清除区域后恢复全场景编辑。
5. Ctrl+Z 撤销，Ctrl+Shift+Z / Ctrl+Y 重做，Ctrl+S 保存。输入框保留原生文本撤销。保存后仍可撤销；撤销后新增编辑会清除当前重做分支。

6. 主视图可使用“分类画刷”直接涂刷目标类别，松手提交一笔，整笔撤销；涂刷期间禁止导航。第一版只支持穿透，沿用已设置的局部区域，不采用框选的深度开关。操作及性能口径见 [画刷分类](画刷分类.md)。

“限制选择深度”以当前视图观察目标为中心，沿观察方向限制厚度，冻结到该次选区。改变相机不会移动已经确认的选区。组合选区表达式最多 128 个节点、深度 24，防止无界累积阻塞计算。

## 运行结构

| 模块                               | 职责                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| shared/selection.mjs               | 区域坐标与选择集合表达式、范围校验                      |
| shared/edits.mjs                   | 新旧编辑命令校验与有序逐点求值                          |
| shared/history.mjs                 | 命令冻结、历史分支和语义保存状态                        |
| shared/workspace.mjs               | 持久化视图状态校验                                      |
| src/editor/useEditHistory.js       | React 历史状态入口                                      |
| src/editor/PointCloudWorkspace.jsx | 局部截取、多视图、组合选区和相机交互                    |
| src/pointcloud/runtime.js          | 单渲染器四视口、共享节点预算、加载调度和过期结果拦截    |
| src/pointcloud/worker.js           | 保留节点基础属性，增量编辑和每节点最多 8 个历史缓存状态 |
| server/project-store.mjs           | SQLite 事务、版本迁移、旧侧车迁移及一致性备份           |

交互只处理加载节点，不扫描全数据集。子视图可请求主视图尚未加载的细节点，所有视口共享节点、解码数据、工作线程池和总预算。空间包围盒先排除不相关的命令；节点按冻结的表达式顺序求值，类别和删除状态不会随 LOD 改变。Worker 结果必须匹配当前数据集、节点实例及编辑版本，连续操作会合并过时工作。

节点有原始属性和有限数量的派生历史状态。新增操作从匹配的历史前缀增量计算；撤销/重做优先使用缓存。首次加载长历史且没有匹配缓存时仍需重放相关命令，这是当前性能边界，缓存不构成无限历史的常数时间保证。

相机、方向锁定和布局会在显式保存时记录，但单纯导航不产生数据撤销步骤，也不改变数据的未保存标记。区域改变及类别定义改变会使工程变脏。未确认的选区目前只在内存，不作为正式编辑历史恢复。

## 工程与数据库

默认结构：

```text
A.sceneloom/
├─ project.sceneloom.json  # 格式版本、数据库相对路径、源数据关联
└─ project.db             # 工程、历史、工作区和恢复状态
```

打开工程入口可恢复局部视图及编辑历史。直接打开 Potree 时，工程在数据目录旁创建并通过相对路径引用源目录；LAS 转换及打包工程则内含 `pointcloud`。点云不进入数据库。普通工程检查元数据与文件大小/修改时间；打包工程保留数据集身份及文件校验信息，移动后仍可重用编辑历史，时间戳变化时回退到内容校验。任意外部源移动后的手动重关联尚未提供。完整目录及使用方式见 [工程存储与打包](工程存储与打包.md)。

| 表                | 实际字段/用途                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------- |
| projects          | id、created_at、updated_at                                                                                 |
| datasets          | id、project_id、source_uri、source_revision、format、metadata_json                                         |
| edit_commands     | dataset_id + id 联合主键、sequence、parent_id、payload_version、payload_json；命令不可变，保留分支记录     |
| snapshots         | id、dataset_id、kind、head_command_id、payload_version、payload_json、created_at；kind 区分 saved/recovery |
| sessions          | dataset_id、saved_snapshot_id、recovery_snapshot_id、revision；事务切换状态引用                            |
| schema_migrations | version、applied_at；配合 PRAGMA user_version 顺序迁移                                                     |

第一版工作区几何、相机、类别配置位于带版本的快照负载中；关系、历史序列、类型和版本保持独立列。后续需要独立查询区域或插件状态时，通过迁移增加表，不直接改变旧负载含义。当前只有活动 saved/recovery 快照，命令保留完整历史及已放弃分支；长期历史清理由未来压实策略控制。

恢复记录短时合并写入，显式保存捕获点击时的不可变状态。事务完成后才显示已保存；保存期间继续编辑保留未保存标记。撤销返回保存状态会同步恢复记录，避免重开时复活旧编辑。命令和工程状态一旦可靠保存即可完整恢复，无需等待全点云物化计算；界面不暴露内部阶段。

SQLite 开启外键、WAL 和 FULL 同步。`POST /api/datasets/:id/backup`，请求体 `{ "directory": "绝对路径的新目录" }`，仅创建一致性数据库及匹配入口，仍引用外部点云；拒绝覆盖已有目录。“打包工程”通过独立 `/api/packages` 任务复制全部点云依赖，并通过 SQLite backup API 捕获一致性快照。不要直接复制正在打开的数据库作为备份；便携副本使用打包功能生成。

## 本轮边界

当前没有全量导出、删除压实、C++ 点级结果物化或八叉树重建。以上应作为独立工具任务实现，不能在普通保存中引入全量扫描。BROTLI 解码、刷选、任意倾斜工作平面及跨设备性能门槛也不属于已完成能力。

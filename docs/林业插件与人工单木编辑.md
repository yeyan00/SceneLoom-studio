# 林业插件与人工单木编辑

2026-10-29，首版人工交互已实现；后续新增的传统自动算法见 [CHM单木分割](CHM单木分割.md)，深度学习等方向暂不实现。

## 使用

打开点云后点击“林业”Ribbon 页签，右侧自动切到“单木”面板。

1. 先框选/多边形选择，再点击“选区新建单木”：自动编号并归入选区，一次 Undo 整体撤回。
2. 也可以直接“新建单木”建立空实例；它自动成为当前单木，后续框选确认和画刷都作用于它。
3. 在单木列表切换当前树。选中对象本身不改变点的归属；点击“归入当前单木”或实际涂刷才写入编辑命令。
4. 默认只处理未分配点；“转入当前单木”允许覆盖其他树的归属。转移后 Undo 恢复原归属。
5. “从当前单木移除”只清除当前树的归属，不删除点，也不清除其他树的归属。画刷移除通过面板开关启用。
6. 单木画刷复用分类画刷：穿透、涂刷期间锁定相机、+/- 或 [/] 改大小、空闲时空格导航、Esc 取消当前笔画、一笔一个撤销步骤。
7. 单木名称可以修改并撤销；保存工程、恢复及打包保留树列表、字段类型与全部编辑历史。

classification 与 treeID 独立。切回点云编辑后分类工具继续操作 classification，不改树木归属；林业工具不自动修改分类。主视图和局部子视图共用结果，后加载节点按相同规则求值。

首次创建前可选 uint16（默认）或 uint32，0 未分配。ID 由后台事务分配，允许不连续，取消或 Undo 后不回收，Redo 恢复原编号。达到类型上限拒绝分配，不截断/回绕。字段升级界面尚未实现，因此首次创建时应按数据规模选择；不要把 ID 当作连续数量统计。

按单木着色使用稳定整数散列；当前树保持正常颜色，其他树及未分配点变暗，所有视图一致。没有全量统计，因此不显示伪造的整树点数。

## 插件入口

`src/plugins/index.jsx` 注册内置插件；`src/plugins/registry.mjs` 校验唯一 ID、必需组件和着色模式冲突。每个插件提供：

| 贡献项 | 职责 |
| --- | --- |
| id / label | 稳定插件标识和 Ribbon 页签名称 |
| Provider | 独立会话/业务状态，通过 host 使用工程和交互服务 |
| Ribbon | 当前页签的分组和按钮 |
| Panel / panelLabel | 独立停靠页签及业务面板 |
| displayModes | 属性显示选择器中的额外模式 |

主界面按注册信息渲染 Ribbon 和停靠面板，不直接编写单木按钮。插件通过 host 的历史、选择、工具、日志错误入口及激活接口协作；没有另一套鼠标监听或撤销栈。

`src/plugins/context.jsx` 的编辑适配器向工作区提供画刷业务目标。分类仍使用原先的默认目标；林业提供 treeID、当前实例和归属策略。几何轨迹、快捷键、相机冻结、实时调度和提交均复用 `useBrush` 与现有运行时。

本版是随程序内置、启动时注册的受信任 UI 插件，不含外部安装、动态热加载或插件市场。独立 EXE 工具插件继续使用原机制；CHM 自动分割已通过后台任务接入。

## 数据与历史

`shared/forestry.mjs` 定义单木状态和校验；`createTree`、`renameTree`、`setAttribute`（当前支持 forestry.treeID）进入统一命令链。创建并归入选区使用单个复合含义命令；当前活动对象从列表选择，不产生数据历史。

树列表、字段定义和名称从有效命令前缀重建，不维护第二份会和 Undo 冲突的活动目录。不可变命令及保存/恢复快照保存在现有 project.db。数据库 v1→v2 新增 `entity_id_counters`，事务分配 ID；命令负载使用 payloadVersion=2，旧分类命令仍可读取。旧版本程序会因数据库版本不支持而拒绝打开，不会忽略新命令后保存。

当前实现只为人工单木提供所需的 treeID 属性闭环，并非全部通用扩展属性阶段已经完成。通用字段创建对话框、其他数值类型赋值、.slattr 物化、逐点属性导出和字段类型升级仍在后续计划中。

Worker 保留原始点序号，按命令执行顺序处理归属和删除：已删除点不再赋值；条件移除只清除操作当时属于目标树的点。所有值保存在 Uint16Array/Uint32Array，颜色映射不将大 ID 转为 float32。

原生 Potree 的 uint16/uint32 treeID 标量可解码和着色；自动编号从声明的最大值后分配，缺少可靠范围时拒绝猜测。首版树列表来自本工程创建的实体，尚未提供从原生 ID 批量生成实体描述/点选导入原有树的流程。

普通保存不重写 octree.bin/hierarchy.bin，也不生成全量扩展属性文件。工程打包携带命令、字段类型和 ID 分配器，并复制所需原始点云；仍可独立重开。

## 验证

`npm.cmd run test:forestry` 自动构建并通过 playwright-cli 验证插件 Ribbon/面板、新建、原子选区创建、归入/转移/移除、画刷、取消、Undo/Redo、名称、保存重开、分类切换和中英文/窄屏。新增单元覆盖点级顺序、增量/冷重放、类型边界和插件注册；接口测试覆盖 ID 不复用、旧库迁移、上限、打包后重开及继续编号。

完整回归通过 26 项单元、7 项接口检查及全部浏览器和转换检查；随后补充的 v1 迁移/上限接口用例也通过，当前接口用例共8项。


Public validation uses generated fixtures only. Private dataset measurements are omitted.

# CHM 水平分块与边界融合

2026-10-30，首版实现。入口仍为“林业 → CHM 单木分割”。

## 数据流程

1. 按当前计算范围遍历 Potree 所有相关节点，每次点数据读取不超过约 4 MiB。应用已有分类/删除命令，累计最高点、地面低值及支持信息，随即释放点块。
2. 在统一 XY 栅格上划分不重叠核心区，默认边长 64 m。每块带缓冲，默认最小值 12 m；实际宽度至少覆盖 `2×地面窗口＋2×地面网格` 和树顶检测邻域，默认实际 20 m。
3. 从累计栅格切出该块及缓冲区，独立生成地面估计、CHM、树顶种子和分水岭。粗地面栅格保持全局相位，不同块不重新定义同一网格的原点。
4. 对相交缓冲区统计冠区重合度，要求双向最佳匹配、Dice ≥0.6、至少4个共同栅格，且树顶距离不超过 `max(2×像元, 0.5×树顶间距)`，才允许合并。
5. 并查集合并还有约束：不能让同一块原本识别的两个不同实例，经其他块的传递匹配被合为一个。仅接触不合并。
6. 每块只写出核心区，同一输出像元只有一个所有者。最后统一实例编号，并按融合后面积过滤过小冠区。缓冲区不重复输出。

同一任务只读取一遍 Potree 点数据。最初逐块回读原始节点的实现，会放大读取量，已被单次扫描方案替换。

## 内存与范围

- 内存包含容量受限的全局输入/输出栅格、一块分割工作区、尚可能相交的邻块标签窗口和实例映射。点数增长不会要求保存全部点。
- 当前仍限制结果200,000个栅格、单块工作区200,000个栅格，规划不超过4096块。分块工作区上限不能视为整个进程的内存上限。
- 预览、命令历史、Worker消息和JSON保存仍会复制结果；旧分割命令也可能积累。因此本轮未取消结果总量保护，没有承诺任意面积的外存计算。
- 超大范围下一步需要将累计栅格、结果、历史引用改为磁盘分块资源，并支持按块预览和恢复。现阶段仍应选局部范围或增大像元。
- 稀疏地面、较大树冠、冠区接触和局部范围外缘仍可能产生不一致；缓冲融合不保证所有数据都等效于整幅分割。局部截取范围之外尚未额外读取地面/树冠上下文。

## 保持现有编辑契约

最终仍生成一个 `segmentTrees` 命令，兼容已有工程、一次撤销/重做、编号预留、点归属策略和后加载节点。源数据不改写。预览和确认继续使用正式编号，计算中可取消；参数改变后旧预览失效。

## 验证

41项相关检查通过：全部单元以及CHM、标签集接口测试。新增跨边界树冠、四块交汇、邻树不误合并、空块、每个核心像元唯一归属、栅格相位、单次累计与逐点块计算一致性检查。Playwright 已验证分块参数、预览确认、Undo/Redo、保存重开、双语和窄屏；林业人工编辑回归通过。


Public validation uses generated fixtures only. Private dataset measurements are omitted.
